# بات تلگرام محلی IPTV — بستهٔ مستقل

این برنامه روی کامپیوتر شما اجرا می‌شود، منوی فارسی دارد و انتشارهای جدید
`Update playlist` را از مخزن عمومی GitHub می‌خواند. به سرور، Docker، Git،
Node یا نصب کتابخانهٔ پایتون نیاز ندارد. **Python 3.10 یا جدیدتر** و اینترنت
متصل به Telegram و GitHub لازم است. فایل EXE نیست و پایتون را همراه ندارد.

## راه‌اندازی در ویندوز

۱. Python 3.10+ را از `https://www.python.org/downloads/` نصب کنید و در نصب،
گزینهٔ **Add Python to PATH** را فعال کنید.

۲. فایل ZIP را کاملاً **Extract** کنید؛ برنامه را از داخل ZIP اجرا نکنید.

۳. فایل **`bot_run.bat`** را دوبار کلیک کنید. پنجره باید باز بماند.

۴. برای بات شخصی، در تلگرام با حساب رسمی **@BotFather** دستور `/newbot` را
اجرا کنید و توکن بگیرید. توکن را **فقط در پنجرهٔ محلی برنامه** وارد کنید؛
هنگام تایپ/چسباندن نمایش داده نمی‌شود. آن را در چت، عکس یا مخزن نفرستید.
اگر GitHub repository پرسیده شد، Enter بزنید تا `4kings6114/IPTV` انتخاب شود.

۵. برنامه در پنجرهٔ محلی عبارتی مانند `/start CODE` نشان می‌دهد. عین همان
عبارت را در **گفت‌وگوی خصوصی با بات خودتان** بفرستید، نه در گروه یا BotFather.
کد واقعی تصادفی است؛ عبارت CODE در این راهنما جای کد واقعی نیست.

۶. پس از پیام اتصال موفق، منوی فارسی ظاهر می‌شود. دفعهٔ اول، آخرین تصویر
منتشرشده برایتان ارسال می‌شود؛ این پیام ادعای انتشار جدید در همان لحظه ندارد.
از آن پس انتشارهای تازه به‌صورت خودکار گزارش می‌شوند.

## لینوکس و مک

در پوشهٔ استخراج‌شده، ترمینال را باز کنید:

```sh
sh bot_run.sh
```

در مک فایل `bot_run.command` هم وجود دارد. ممکن است لازم باشد ابتدا در ترمینال
`chmod +x bot_run.command bot_run.sh` بزنید و اجازهٔ اجرای فایل دانلودشده را
طبق تنظیمات امنیتی سیستم بدهید. نیاز پایتون در همهٔ سیستم‌ها یکسان است.

## منو و دستورها

- `/start` و `/help`: منو و راهنما
- `/links`: لینک اصلی، اصلی+جایگزین دستی، فارسی، اخبار، موسیقی، ورزش، فیلم،
  کودک، علاقه‌مندی‌های پروژه و نسخهٔ قبلی پلی‌لیست
- `/search bbc`: جستجو در آخرین گزارش؛ حداکثر ۱۰ نتیجه و لینک فهرست پلیر.
  دکمهٔ جستجو را هم می‌توانید بزنید و نام شبکه را بفرستید.
- `/stats`: آمار و دسته‌بندی‌ها
- `/status`: آخرین وضعیت workflow به نام Update playlist، با لینک GitHub
- `/changes`: خلاصهٔ آخرین انتشار دریافت‌شده
- `/profiles`: پروفایل‌های منتشرشده مانند فارسی/انگلیسی و کم‌مصرف
- `/dashboard`: آدرس GitHub Pages؛ فقط در صورت فعال‌بودن Pages قابل دسترس است

در فایل `playlist-alternatives.m3u` ورودی `[جایگزین]` را **دستی** انتخاب کنید.
`playlist-backup.m3u` نسخهٔ قدیمی فهرست اصلی است، نه جایگزین هر شبکه.
خالی‌بودن `favorites.m3u` به معنی خرابی بات نیست؛ علاقه‌مندی‌های پروژه ممکن
است خالی باشند. بات لینک M3U می‌فرستد و ویدئو را میزبانی یا پخش نمی‌کند.

## گزارش خودکار چگونه کار می‌کند؟

- برنامه هر **۵ دقیقه** انتشارهای فایل `build_report.json` در شاخهٔ `main`
  را از GitHub بررسی می‌کند. تصویر گزارش از همان commit خوانده می‌شود تا
  آمار انتشارهای مختلف مخلوط نشود.
- آمار شامل تعداد شبکه‌ها، اضافه/حذف، تغییر آدرس، کیفیت و بازیابی، تعداد
  شبکه‌های دارای لینک دوم، چند نمونهٔ نام‌های جدید/حذف‌شده و لینک‌های M3U است.
- تغییرات صرفاً کد یا اجراهای موفق بدون تغییر گزارش، انتشار جدید تلقی نمی‌شوند.
  شکست/اتمام مهلت/لغو آخرین اجرای workflow نیز یک بار اعلان می‌شود.
- خاموشی کامپیوتر، بسته‌شدن پنجره، Sleep و قطع اینترنت باعث توقف دریافت می‌شوند.
  پس از اجرای دوباره، وضعیت قبلی خوانده و حداکثر **۲۰ انتشار اخیر** از قدیم
  به جدید بررسی می‌شوند. در اولین نصب فقط آخرین تصویر ارسال می‌شود.
- اگر مرجع قبلی از ۲۰ انتشار اخیر خارج شده یا تاریخچه بازنویسی شده باشد، پیام
  هشدار شکاف تاریخچه می‌آید؛ پوشش کامل تاریخچهٔ قدیمی‌تر تضمین نمی‌شود.
- خطای شبکه و پاسخ نامعتبر گزارش نباید گزارش قبلی را پاک کند. پس از خطای
  دریافت، تلاش بعدی خودکار است؛ محدودیت نرخ GitHub می‌تواند وقفه را بیشتر کند.
- گزارش‌های موفق در `data/state.json` ثبت می‌شوند تا پس از راه‌اندازی مجدد
  دوباره ارسال نشوند. پاک‌کردن state، کپی بسته روی کامپیوتر دیگر یا قطع برق
  بین پذیرش پیام و ذخیرهٔ state می‌تواند باعث تکرار پیام شود؛ تضمین دقیقاً یک‌بار نداریم.
- داده‌های جستجو خلاصهٔ محلی گزارش‌اند؛ بعد از هر انتشار تازه می‌شوند و تضمین
  سلامت لحظه‌ای استریم در کشور یا پلیر شما نیستند.
- هیچ دستور بات، workflow را اجرا یا مخزن/پلی‌لیست‌ها را تغییر نمی‌دهد. GitHub
  Token لازم نیست؛ دسترسی خواندن مخزن عمومی کافی است. دکمهٔ Update مخرب نداریم.

## توکن فعلی بات و تداخل با سرویس قبلی

**پیشنهاد امن: یک بات جدید مخصوص اجرای محلی بسازید.** منوی تصاویر شما ممکن
است توسط برنامه‌ای دیگر میزبانی شود؛ این بسته آن سرویس را حذف یا متوقف نمی‌کند.

اگر همان توکن را استفاده می‌کنید:
- برنامهٔ قبلی که `getUpdates` می‌خواند باید متوقف شود؛ دو poller هم‌زمان
  باعث خطای Telegram 409 می‌شوند. یک قفل محلی هم اجرای دوبارهٔ همین پوشه را می‌گیرد.
- اگر webhook فعال باشد، برنامه متوقف می‌شود و **خودکار webhook را حذف نمی‌کند**.
  سرویس قبلی را با اطلاع خودتان متوقف/تنظیم کنید یا از بات جدید استفاده کنید.
- اعلان یک‌طرفهٔ GitHub Actions با `sendMessage` از نظر polling تداخل ندارد؛
  اما استفاده از یک بات/چت برای هر دو اعلان Actions و محلی می‌تواند دو گزارش
  جدا ایجاد کند. این بسته تنظیمات یا Secrets گردش‌کار فعلی را دست‌کاری نمی‌کند.

## تنظیمات خصوصی و امنیت

راه‌اندازی اول این فایل‌ها را در پوشهٔ `data` ایجاد می‌کند:
- `config.json`: **حاوی توکن خصوصی**، نام مخزن، شاخه، شناسهٔ مالک و فاصلهٔ پایش
- `state.json`: مرجع انتشارها، صف گزارش‌ها و offset تلگرام
- `report.json`: کش خلاصهٔ گزارش عمومی؛ بدون آدرس‌های استریم و manifest ویرایشگر
- `bot.lock`: قفل اجرای هم‌زمان

توکن رمزگذاری‌شده نیست؛ پوشهٔ برنامه را در حساب شخصی و درایو امن خودتان نگه
دارید. در Unix فایل‌های نوشته‌شده مجوز ۶۰۰ دارند؛ در ویندوز امنیت دسترسی به
ACL پوشهٔ حساب شما بستگی دارد. **پوشهٔ data را به دیگران ندهید و آپلود نکنید.**
توکن لو رفت: در BotFather آن را لغو/عوض کنید، نه اینکه فقط فایل را پاک کنید.

پس از اتصال، فقط شناسهٔ عددی همان گفت‌وگوی خصوصی اجازهٔ پاسخ‌گرفتن دارد؛
نام کاربری ملاک نیست. اولین `/start` از یک غریبه نمی‌تواند مالک را تعیین کند؛
کد تصادفی پنجرهٔ محلی لازم است. پیام‌های گروه‌ها و دیگران بدون پاسخ نادیده گرفته می‌شوند.

TLS عادی فعال است، درخواست‌ها timeout و سقف حجم دارند و URL حاوی توکن در
لاگ چاپ نمی‌شود. برنامه درخواست استریم و تصویر لوگو نمی‌فرستد. تلگرام پیام‌ها
و GitHub آدرس IP کامپیوتر شما را می‌بینند. نیاز به دسترسی Administrator ندارد.

## تغییر توکن، اتصال مجدد و عیب‌یابی

ابتدا با `Ctrl+C` برنامه را متوقف کنید. سپس در همان پوشه اجرا کنید:

```sh
python bot_run.py --setup
```

در ویندوز می‌توانید `bot_run.bat --setup` را در CMD اجرا کنید. راه‌اندازی مجدد
توکن و مالک را جایگزین و state را پاک می‌کند؛ آخرین تصویر دوباره ارسال می‌شود.
می‌توانید پس از بستن برنامه، `data/config.json` را با قالب `config.example.json`
ویرایش کنید؛ فاصلهٔ پایش باید بین ۱۲۰ تا ۳۶۰۰ ثانیه باشد. تنظیم ۳۰۰ توصیه می‌شود.

- خطای 401/404: توکن را فقط روی کامپیوتر بررسی و در صورت نیاز تنظیم مجدد کنید.
- خطای 409: برنامهٔ دیگری همین بات را می‌خواند یا webhook فعال است.
- GitHub 403/429: احتمال محدودیت نرخ؛ برنامه با فاصلهٔ بیشتر دوباره تلاش می‌کند.
- خطای `Invalid report cache`: برنامه را ببندید، از `data/report.json` نسخهٔ پشتیبان
  بگیرید و فقط همان فایل را حذف کنید. کش از انتشار قبلی بازسازی می‌شود؛
  `state.json` را حذف نکنید تا گزارش‌های قدیمی دوباره ارسال نشوند.
- مشکل اتصال به Telegram: دسترسی اینترنت/فیلترینگ و تنظیمات پراکسی سیستم را
  بررسی کنید. برنامه از تنظیمات استاندارد urllib مانند HTTPS_PROXY استفاده می‌کند؛
  رمز پراکسی را هم در چت یا فایل‌های عمومی ننویسید.
- پیام اول هنوز نیامده: `/start CODE` را در چت خصوصی بات خودتان بفرستید و
  پنجرهٔ محلی را برای خطای اتصال بررسی کنید. دانلود گزارش اولیه ممکن است زمان ببرد.
- برای خروج: `Ctrl+C`. با اجرای دوبارهٔ `bot_run` ادامه می‌دهد. نصب سرویس،
  اجرای خودکار هنگام روشن‌شدن و فایل EXE در این نسخه وجود ندارد.

## ساخت دوبارهٔ بسته از مخزن

از ریشهٔ مخزن:

```sh
python tools/package_local_bot.py
```

بسته فقط از فهرست صریح کد، اجراگرها، راهنما، نمونهٔ تنظیمات و `data/README.md`
ساخته می‌شود؛ هیچ توکن، state، گزارش حجیم یا دادهٔ شخصی وارد ZIP نمی‌شود.
