# نگه‌داری و بازیابی امن امضای نسخهٔ آزمایشی

این راهنما برای **مالک مخزن روی رایانهٔ شخصی خودش** است، نه برای نصب‌کنندهٔ APK و نه برای اجرا در Arena یا CI. هیچ رمز، توکن، فایل keystore، کلید خصوصی یا پوشهٔ بازیابی را در چت نفرست.

**وضعیت اولیهٔ این تغییر:** ابزارها آماده‌اند، اما تا وقتی مراحل زیر را انجام نداده‌ای، انتقال واقعی به Secret و ایجاد پشتیبانِ مالک انجام نشده است. `policy.json` عمداً روی `legacy-cache-during-owner-setup` است؛ کش قبلی هنوز لازم است. آزمون ابزار با کلید مصنوعی، جای بازیابی کلید واقعی را نمی‌گیرد.

## چه چیزی حفظ می‌شود؟

- همان شناسهٔ برنامهٔ `io.github.fourkings6114.iptv.trial` و همان امضای نسخه‌های تحویل‌شدهٔ ۰.۱.۲/۰.۱.۳؛ **کلید جایگزین ساخته نمی‌شود**.
- SHA-256 گواهی عمومی مجاز:

  ```text
  eba2f7bdb4cfea267f4c30cedba8b2956f9c86ed3d5363512291fd3d6bd29c48
  ```

- این کار حفاظت از **کلید آزمایشی موجود** است، نه تبدیل آن به کلید انتشار نهایی/Play. رمز استاندارد debug از قبل عمومی است؛ حفاظت واقعی را Secret و رمزگذاری پشتیبان فراهم می‌کنند.
- روی گوشی چیزی را حذف نکن و **Clear data نزن**. این مراحل کاری با فهرست‌ها، علاقه‌مندی‌ها یا دادهٔ گوشی ندارند.

## ۱. پیش‌نیازها، فقط روی رایانهٔ خودت

این ابزارها باید از منبع رسمی نصب و در `PATH` باشند: **Python 3.11+، Git، GitHub CLI (`gh`)، JDK 17** شامل `keytool` و `jarsigner`، و **age / age-keygen نسخهٔ 1.3.2 یا جدیدتر**. برای نگه‌داری کلید نیازی به Android SDK نیست؛ ساخت APK در Actions انجام می‌شود.

age رسمی: [FiloSottile/age — v1.3.2](https://github.com/FiloSottile/age/releases/tag/v1.3.2). در ویندوز x64 بستهٔ `age-v1.3.2-windows-amd64.zip` را بگیر و پیش از استخراج با PowerShell بررسی کن:

```powershell
Get-FileHash "$HOME\Downloads\age-v1.3.2-windows-amd64.zip" -Algorithm SHA256
```

مقدار لازم برای **همین فایل و همین نسخه**:

```text
f48d8f8f9ebe903ab5027ed067652f2cc1db94bc206976430133b905dcd8e8c7
```

در صورت اختلاف، اجرا نکن. `age.exe` و `age-keygen.exe` را در یک مسیر شخصی مطمئن، خارج از مخزن، قرار بده و آن مسیر را به `PATH` اضافه کن؛ بعد ترمینال تازه باز کن. برای Mac/Linux از روش رسمی معرفی‌شده در مخزن age استفاده کن. نصب‌کنندهٔ پین‌شدهٔ `install_ci_age.py` مخصوص runner لینوکس است، نه نصب خودکار روی رایانهٔ شخصی.

در ترمینال معمولی و تعاملی، وارد حساب مالک GitHub شو؛ احراز هویت فقط بین رایانهٔ خودت و GitHub است:

```sh
gh auth login --hostname github.com --web
gh auth setup-git
```

ابزار به دسترسی نوشتن روی همین شاخه، Secrets و Actions نیاز دارد. خطای 403 یعنی دسترسی ورود محلی/سیاست مخزن کافی نیست؛ توکن را در چت نفرست. دسترسی قبلی Arena به Secrets با 403 مسدود بود و این راهنما آن را دور نمی‌زند.

یک کپی تمیز از **همین شاخه** بگیر:

```sh
git clone --single-branch --branch arena/df65ff7a-iptv https://github.com/4kings6114/IPTV.git iptv-owner-setup
cd iptv-owner-setup
python android/tools/signing_owner.py doctor
```

در ویندوز در صورت نیاز `python` را با `py -3`، و در Linux/macOS با `python3` جایگزین کن. نام و ایمیل commit باید در Git محلی خودت تنظیم شده باشد. از checkout دارای تغییرات شخصی استفاده نکن. ابزار فقط همین شاخه را fast-forward می‌کند، فایل عمومی درخواست/سیاست را commit و push می‌کند؛ شاخه‌ای نمی‌سازد یا عوض نمی‌کند و روی `main` چیزی نمی‌فرستد.

## ۲. ساخت هویت بازیابی محلی و درخواست پشتیبان رمزگذاری‌شده

```sh
python android/tools/signing_owner.py init
python android/tools/signing_owner.py request
```

- `init` یک **هویت رمزگشایی age** می‌سازد؛ این هویت با کلید امضای APK فرق دارد. عبارت بازیابی را فقط در پرسش محلی age وارد کن و جداگانه در مدیر رمز مطمئن نگه دار. هویت خصوصی به‌شکل رمزگذاری‌شده ذخیره می‌شود؛ نسخهٔ روشن آن در Git یا artifact نوشته نمی‌شود.
- پوشهٔ پیش‌فرض خارج از Git است: `~/.iptv-hamrah-signing`؛ در ویندوز معمولاً `%USERPROFILE%\.iptv-hamrah-signing`. در POSIX دسترسی پوشه 700/فایل‌های خصوصی 600 و در ویندوز ACL مالک/SYSTEM تنظیم می‌شود. این حفاظت جای امنیت خود رایانه یا رمزگذاری دیسک را نمی‌گیرد.
- `request` فقط گیرندهٔ **عمومی** age و شناسهٔ درخواست را در `android/signing/owner-request.json` روی همین شاخه push می‌کند. CI گواهی و قابلیت امضای کلید موجود را بررسی کرده، مستقیماً در حافظه رمزگذاری می‌کند و **فقط فایل `.age`** را بارگذاری می‌کند. کلید امضای روشن، رمز بازیابی و هویت خصوصی به artifact یا log نمی‌روند.
- مسیر CI: **Android owner signing recovery**. artifact رمزگذاری‌شده ۷ روز نگه‌داری می‌شود؛ این artifact و کش هیچ‌کدام پشتیبان دائمی نیستند. بدون درخواست عمومی تازه، تغییرات معمول کد/سیاست پشتیبان زنده صادر نمی‌کنند.

## ۳. بازیابی واقعی، ثبت Secret و اثبات ساخت با Secret

```sh
python android/tools/signing_owner.py finish
```

ترمینال را باز نگه دار؛ ابتدا پشتیبان و سپس ساخت/آزمون‌های شبیه‌ساز ممکن است چندین دقیقه طول بکشند. رمز را فقط در پرسش محلی age وارد کن. ابزار به‌ترتیب:

1. artifact را برای همان commit/درخواست می‌گیرد؛ هش GitHub و هش گزارش CI را تطبیق می‌دهد؛ فقط ciphertext را نگه می‌دارد.
2. آن را روی رایانهٔ خودت رمزگشایی می‌کند؛ متن روشن فقط در حافظه و keystore موقت در پوشهٔ خصوصی، خارج از Git، برای `keytool/jarsigner` استفاده و سپس حذف می‌شود. حذف فایل، تضمین پاک‌سازی فیزیکی SSD یا حافظه نیست.
3. گواهی ثابت را مقایسه و با امضا/بررسی یک چالش، وجود **کلید خصوصی قابل‌استفاده** را ثابت می‌کند؛ گواهی عمومی به‌تنهایی کافی نیست.
4. با ورود محلی `gh`، Secret به‌نام `IPTV_SIGNING_KEYSTORE_B64` را ثبت می‌کند. مقدار از stdin می‌رود، نه آرگومان فرمان، فایل base64 یا خروجی چت. base64 به‌تنهایی رمزگذاری نیست؛ `gh` مقدار را برای GitHub رمزگذاری می‌کند.
5. سیاست عمومی را به `actions-secret` تغییر داده و فقط روی همین شاخه push می‌کند. از این نقطه، نبود Secret باعث **توقف** است؛ برگشت پنهانی به کش یا تولید کلید جدید نداریم.
6. موفقیت ساخت و امضای APK و **هر دو آزمون ارتقا/پخش API 31 و 33** را برای همان commit و با منبع `actions-secret` بررسی می‌کند. ارتقا با `install -r` از APK بازسازی‌شدهٔ سورس ثابت ۰.۱.۲ و حفظ دادهٔ نمونه انجام می‌شود؛ این آزمون گوشی واقعی نیست.

این فرمان **کش قبلی را حذف نمی‌کند**. اگر قطع شد یا CI هنوز تمام نشده است:

```sh
python android/tools/signing_owner.py status
```

اگر Secret ثبت شده ولی مرحلهٔ فعال‌سازی کامل نشده، `finish --replace` پس از بازیابی مجددِ همین پشتیبان می‌تواند عملیات را تکرار کند. Secret موجود بدون گزینهٔ صریح `--replace` بازنویسی نمی‌شود. اگر artifact منقضی شده و هنوز نسخهٔ محلی معتبر نداری، `request --new-request` بزن؛ کش را نگه دار. اگر نسخهٔ محلی معتبر داری، مسیر `restore` زیر به artifact وابسته نیست.

## ۴. نسخهٔ آفلاین و سپس حذف اختیاری کش قدیمی

**کل پوشهٔ بازیابی** را روی حافظهٔ آفلاین مطمئن کپی کن: `owner-identity.age`، `owner-state.json` و `iptv-signing-….age`. عبارت بازیابی را جدا نگه دار؛ داشتن فایل‌ها بدون آن برای بازیابی کافی نیست. پوشه را در Git، چت، سایت یا artifact عمومی بارگذاری نکن؛ حتی فایل رمزگذاری‌شده هم باید خارج از checkout بماند.

از کپی آفلاین یک بازیابی آزمایشی انجام بده؛ نمونهٔ ویندوز (مسیر واقعی خودت را جایگزین کن):

```sh
python android/tools/signing_owner.py --state-dir "D:\IPTV-signing-offline" verify-backup
```

`verify-backup` فقط محلی است: رمزگشایی، تطبیق گواهی و اثبات کلید خصوصی؛ هیچ درخواست GitHub یا تغییر Secret/کش ندارد. روی Linux/macOS مسیر حافظهٔ آفلاین خودت را بده.

فقط پس از موفقیت آن و `status`، اگر خواستی کش قدیمی را حذف کن:

```sh
python android/tools/signing_owner.py purge-cache --offline-copy-confirmed
```

این فرمان دوباره بازیابی محلی و موفقیت CI با Secret را اثبات می‌کند و فقط کش با کلید `android-trial-signing-v1` مربوط به `arena/df65ff7a-iptv` را حذف می‌کند؛ بقیهٔ کش‌ها دست نمی‌خورند. اگر شاخه بعد از commit تأییدشده جلو رفته باشد، عمداً متوقف می‌شود؛ ابتدا با `restore --replace` دوباره همان هویت را فعال/تأیید کن. صرف وجود یک Secret یا سبزشدن آزمون مصنوعی، مجوز حذف کش نیست.

## بازیابی در آینده

روی رایانهٔ امن، ابزارهای رسمی را نصب و کپی تمیز همین شاخه را بگیر. پوشهٔ کامل آفلاین را خارج از Git برگردان:

```sh
python android/tools/signing_owner.py --state-dir "PATH-TO-RESTORED-FOLDER" verify-backup
python android/tools/signing_owner.py --state-dir "PATH-TO-RESTORED-FOLDER" restore
```

اگر Secret از قبل وجود دارد و عمداً می‌خواهی **همین کلید بررسی‌شده** دوباره ثبت شود، `restore --replace` بزن. این مسیر به کش قدیمی یا artifact منقضی‌شده نیاز ندارد؛ ساخت/آزمونِ تأیید به GitHub نیاز دارد.

گم‌شدن هم‌زمان پشتیبان و Secret، یا گم‌شدن عبارت بازیابی همراه با کلید قابل‌دسترس، ممکن است ارتقای همین برنامه را ناممکن کند. ساخت کلید تازه راه حفظ دادهٔ نصب قبلی نیست. دسترسی نوشتن مخزن و workflowها را محدود نگه دار؛ Actions Secrets در برابر workflow مخربِ فرد دارای دسترسی نوشتن، مرز امنیتی مستقل نیست.
