# Security and publication boundaries

- Python 3.10+ with a standard-library-only runtime; use a maintained Python release (3.12+ recommended). Node/jsdom are development-only, not needed to build playlists or open the dashboard.
- Do not put passwords, account cookies, API keys, Telegram secrets or private playlists in this **public** repository, including manual/override/favorites files. Public-source signed links may expire and are not proof of viewing rights.
- Probes only accept HTTP(S), make bounded GETs, reject HTML/JSON masquerading as streams, cap redirects/HLS depth and drop authorization/cookies on cross-origin redirects and HLS children. This is a trusted, scheduled repository tool, not an HTTP proxy exposed to browser users; local HTTP URLs remain supported for intentional local use/tests.
- Source/resource caps, compressed/expanded XML caps, DTD/entity rejection, parser-summary limits and shared cooperative wall/receive-byte budgets apply. Workflow `timeout` provides an additional hard process deadline. These budgets do not measure TCP/TLS overhead or external decoder byte traffic; ffmpeg has its own count/time/probe limits.
- Optional ffmpeg/ffprobe run without a shell or stdin, with network-only protocol allowlists and fixed deadlines. Keep the host's decoder packages updated. Samples cannot prove all-channel playback, legal access, absence of DRM or availability in another country. Missing/crashed tools must be reported, never called decoded.
- Diagnostics redact URL userinfo, query values, fragments and pipe headers; known sensitive path patterns are hidden. This is conservative best-effort redaction, **not** a general secret scanner. Never rely on it to make private input safe to publish.
- The public editor manifest only contains approved, exportable streams and allowlisted metadata/directives. Known credentials, sensitive headers and DRM licence properties are omitted; exact benign referer/user-agent/origin headers are retained when necessary. Pages stages only named public outputs, excludes input/cache/log directories and refuses failed/dry/blocked builds. Signed/private streams may therefore be absent from Pages downloads; the production M3U is not silently rewritten by staging.
- Raw link-health/request caches are no longer uploaded as diagnostic artifacts. Actions caches still contain original public-source playlists, request fingerprints, observations and (where supplied by public providers) signed variant URLs. GitHub Actions caches are not a secret vault, and artifact retention is bounded to 14 days (Pages artifact: one day).
- The dashboard makes no requests, plays no media, loads no remote images/CDN and sends no preferences. JSON escapes script terminators; DOM uses text nodes; executable inline JS is restricted by a generated SHA-256 CSP hash. Local configuration imports are size/schema checked. Downloads stay on the user's device; they do not write the repository.
- Workflow actions are pinned to reviewed official release SHAs with weekly Dependabot PRs. Checkout does not persist credentials. Only the main publisher has contents-write; only deployment jobs have Pages-write/OIDC. Telegram credentials are scoped to its step. Experimental branches cannot invoke the production publisher. Preview Pages publication is explicit and labelled, and may need owner approval under the `github-pages` environment rules.
- One-time Pages enablement needs owner permissions beyond the current integration's capabilities (the API returned 403 in this session). Enable **Settings → Pages → Source: GitHub Actions**, or review/reconnect the GitHub integration with the appropriate permissions. Never paste credentials into chat or add them to workflows.

## Interactive Telegram bot

- `telegram_bot.py` is separate from the scheduled notification sender. It is private by default: missing chat IDs fail configuration, not open access. Group access allows all group members unless `BOT_ALLOWED_USER_IDS` further restricts them. Public mode must be explicitly enabled; in-memory rate/session limits are not a distributed anti-abuse system.
- Keep the bot token in the environment or an owner-readable `.env`, never in launchers, browser URLs, issues, or Git. The sample has no credentials or personal chat IDs. Environment files are parsed as literals, never sourced/evaluated. API failures are logged without token-bearing URLs, response bodies, or user messages; redirects are disabled.
- Chat discovery, command registration and webhook deletion are explicit owner CLI actions. Normal startup never deletes a webhook or drops pending updates. Offline config checking and cursor migration make no network calls. State uses a per-bot namespace, a local process lock and atomic cursor writes; no exact-once or cross-server lock guarantee is made.
- The bot never fetches arbitrary chat-supplied URLs, probes video streams, rebuilds playlists or writes repository inputs. Its known project downloads have size/time limits and validated, age-bounded cache fallback. Search sessions live only in memory and are scoped to their user/chat. Cursor/lock files contain no token or message text.

Report suspected secret exposure privately to the repository owner and rotate exposed credentials; do not reproduce them in public issues or test fixtures.
